# 为 Oddmash 做贡献

[English](../../CONTRIBUTING.md) · [한국어](../ko/CONTRIBUTING.md) · [日本語](../ja/CONTRIBUTING.md) · **简体中文**

公开仓库的 Issue 和 PR 标题及正文、公开评审讨论、贡献模板、提交信息与变更日志均使用英语。产品文档保留现有的多语言策略，必要时提供翻译支持。

感谢你帮助改进 Oddmash 项目。

Oddmash 是由个人运营的独立软件工作室。公开仓库欢迎范围明确的自发贡献，但不设长期招募计划，也不要求贡献者加入持续运营的社区。是否接纳变更取决于维护者优先级和各项目公开的范围。

## 报告问题

请在相关项目中创建 Issue，说明预期行为、实际行为和复现步骤，并附上项目版本及相关环境信息。请使用公开或本地测试页面和模拟数据，并从日志和截图中移除凭据、私密页面内容及个人数据。

## 提议变更

新增功能或涉及项目多个部分的变更，请先创建 Issue。小范围修复可以直接提交拉取请求，并说明改动会影响哪些行为。

## 项目 README 编写规范

- 把 README 写成产品介绍页。开头说明产品能做什么、适合谁，并给出一个具体的使用场景。
- 用截图、短视频、游戏画面或演示展示实际用法。为图片添加描述性替代文本，将示意图明确标注为示意，并使用示例数据。
- 不要在 README 中放置仓库配置、安装、本地运行命令、实现说明、构建、测试、发布或贡献流程。
- 所有开发和验证说明都应放在项目的 `CONTRIBUTING.md` 中；需要时可在 README 页脚简短链接。
- 同步更新英语、韩语、日语和简体中文版本的内容、语言链接及视觉素材。

共用 Node CI 的使用方式请参阅[英文贡献指南](../../CONTRIBUTING.md#shared-node-checks)。

## 通用开发基线

- 将仓库特定的工作约定放在根目录 `AGENTS.md`。从[组织通用基线](../../AGENTS.md)开始，只添加产品、隐私、发布、引擎、UI 与设计实际需要的规则。
- CI 权限保持最小化，并将复用工作流固定到已审查的提交。运行时矩阵、浏览器或引擎配置、部署与发布检查由各产品仓库负责。
- 产品特定的 UI 与视觉规则保留在项目中。只有多个产品都需要同一项稳定行为时，才将令牌或组件提升到共享包。
- 不要在示例、测试夹具、日志、截图、提示词或评审评论中放入凭据、签名材料、用户数据或仅限生产环境的值。
- AI 代码评审只提供建议。它必须遵守仓库的 `AGENTS.md`，说明依据和置信度，避免重复评论，并且不得自动批准、合并、发布或修改机密。参阅 [AI 代码评审计划](../AI-CODE-REVIEW.md)。

## 提交拉取请求

- 默认创建 Ready for review 的拉取请求，即使远程 CI 或评审仍在进行。仅在明确要求、实现尚未实质完成，或缺少关键验证证据导致评审具有误导性时使用 Draft；记录原因，并在解决后及时转为可评审状态。
- 控制变更范围，有相关 Issue 时请附上链接。
- 按照项目的 `CONTRIBUTING.md` 配置环境并运行检查，在拉取请求中记录结果。
- 说明权限、采集数据、公开 API、部署或发布行为的变化。
