# Oddmash에 기여하기

[English](../../CONTRIBUTING.md) · **한국어** · [日本語](../ja/CONTRIBUTING.md) · [简体中文](../zh-CN/CONTRIBUTING.md)

공개 저장소의 이슈·PR 제목과 본문, 공개 리뷰 논의, 기여 템플릿, 커밋 메시지, 변경 이력은 영어로 작성합니다. 제품 문서의 기존 다국어 정책은 유지하며 필요한 경우 번역을 지원합니다.

Oddmash 프로젝트를 개선하는 데 함께해 주셔서 감사합니다.

Oddmash는 1인 독립 소프트웨어 스튜디오입니다. 공개 저장소에는 범위가 분명한 자발적 기여를 환영하지만, 상시 팀원 모집이나 장기적인 기여자 커뮤니티 참여를 전제하지 않습니다. 반영 여부는 유지관리 우선순위와 각 프로젝트가 공개한 범위에 따라 결정합니다.

## 문제 보고

관련 프로젝트에 이슈를 등록해 주세요. 기대한 동작, 실제 동작, 재현 절차와 함께 프로젝트 버전 및 관련 환경을 알려 주세요. 공개 또는 로컬 테스트 페이지와 가상 데이터를 사용해 주세요. 로그와 스크린샷에서 인증 정보, 비공개 페이지 내용, 개인 데이터를 제거해 주세요.

## 변경 제안

새 기능이나 프로젝트의 여러 부분에 영향을 주는 변경은 이슈를 먼저 열어 주세요. 작은 수정은 풀 리퀘스트를 열고 어떤 동작이 달라지는지 설명해 주세요.

## 프로젝트 README 작성 기준

- README는 제품 소개 페이지로 작성합니다. 첫 부분에서 무엇을 하는 제품인지, 누구에게 도움이 되는지, 어떤 상황에 쓰는지 사례 하나로 보여 주세요.
- 스크린샷, 짧은 녹화, 게임 플레이 캡처 또는 데모로 제품 사용 모습을 보여 주세요. 이미지에 설명이 담긴 대체 텍스트를 넣고, 예시 이미지는 예시라고 표시해 주세요. 시각 자료에는 샘플 데이터를 사용해 주세요.
- 저장소 설정, 설치, 로컬 실행 명령, 구현 설명, 빌드, 테스트, 릴리스, 기여 절차는 README에 넣지 마세요.
- 개발과 검증에 관한 모든 안내는 프로젝트의 `CONTRIBUTING.md`에 작성하세요. 필요하면 README 하단에서 짧게 링크합니다.
- 한국어·일본어·중국어 간체·영어 버전의 내용, 언어 이동 링크, 시각 자료를 함께 갱신해 주세요.

공통 Node CI 사용법은 [영문 기여 안내의 공통 Node 검사](../../CONTRIBUTING.md#shared-node-checks)를 참고하세요.

JavaScript/TypeScript 저장소 내부에서는 `package.json`에 고정한 공통 pnpm 버전과 `pnpm-lock.yaml`을 사용합니다. CI에서는 `pnpm install --frozen-lockfile`로 설치합니다. 공개 npm 배포 및 외부 사용자의 npm, Yarn, Bun 설치 안내는 유지합니다.

## 공통 개발 기준

- 저장소별 작업 기준은 루트 `AGENTS.md`에 둡니다. [조직 공통 기준](../../AGENTS.md)에서 시작하되 제품·개인정보·릴리스·엔진·UI·디자인에 실제로 필요한 규칙만 추가합니다.
- CI 권한은 최소로 유지하고, 재사용 워크플로는 검토한 커밋에 고정합니다. 실행 환경, 브라우저나 엔진 설정, 배포 및 릴리스 검사는 각 제품 저장소가 관리합니다.
- 제품별 UI와 시각 디자인 규칙은 해당 프로젝트에 둡니다. 둘 이상의 제품에서 같은 동작이 안정적으로 필요할 때만 토큰이나 컴포넌트를 공통 패키지로 올립니다.
- 인증 정보, 서명 자료, 사용자 데이터, 운영 전용 값을 예시·픽스처·로그·스크린샷·프롬프트·리뷰 댓글에 넣지 않습니다.
- AI 코드 리뷰는 참고 의견만 제공합니다. 저장소 `AGENTS.md`를 따르고 근거와 확신도를 표시하며, 중복 댓글을 피하고, 자동 승인·병합·배포·시크릿 변경을 하지 않습니다. [AI 코드 리뷰 계획](../AI-CODE-REVIEW.md)을 참고하세요.

## 풀 리퀘스트 제출

- 원격 CI나 리뷰가 아직 진행 중이어도 기본적으로 리뷰 가능한 일반 PR(Ready for review)로 제출합니다. 명시적인 요청, 실질적으로 미완성인 구현, 또는 리뷰를 오해하게 할 핵심 검증 근거 부족에만 Draft를 사용합니다. 사유를 기록하고 해결되면 리뷰 가능한 상태로 전환합니다.
- 변경 범위를 좁게 유지하고 관련 이슈를 반드시 링크하세요. 통합 브랜치 또는 부분 작업은 `Refs #123`, 완료된 기본 브랜치 병합만 `Closes #123`을 사용합니다.
- 프로젝트의 `CONTRIBUTING.md`에 따라 개발 환경을 설정하고 검사를 실행해 주세요. 풀 리퀘스트에 결과를 적어 주세요.
- 권한, 수집 데이터, 공개 API, 배포 또는 릴리스 동작의 변경 사항을 설명해 주세요.

## 기여 양식 검사

- [공통 PR 양식](../../PULL_REQUEST_TEMPLATE.md)의 필수 항목을 모두 작성하고 제목과 유지관리자 작업 브랜치 커밋 제목에 `fix: clarify focus` 같은 유형 접두사를 사용하세요. 외부 기여자 커밋과 기존 릴리스 병합 이력은 수정하지 않습니다.
- 공개 저장소 웹 이슈 양식에는 필수 입력 필드가 있습니다. 비공개 저장소, API/CLI 생성, 수정, 유지관리자의 빈 이슈는 양식 검사를 우회할 수 있으므로 에이전트는 직접 양식과 라벨을 검증해야 합니다.
- [공통 CI 검사](../../CONTRIBUTING.md#contribution-format-checks)는 읽기 전용으로 PR 제목과 본문 구조, 로컬 이슈 링크 등을 검사합니다. 실제 근거와 언어 검토는 별도로 필요합니다. 각 저장소는 검토된 CI 버전으로 갱신하고 PR 수정 이벤트를 활성화하며 기존 필수 상태 검사와 권한을 유지해야 합니다.
